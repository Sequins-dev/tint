# Initial compiler executable

`tint-compiler <project-root> <output>` reads the explicit compiler source catalog,
loads its module graph, invokes the shared hosted build driver, and publishes an
executable output. The first CLI compiles this project; generic configuration-file
syntax and arbitrary project discovery are deferred.

`catalog.ts` is generated by `tools/generate-compiler-catalog.ts` from workspace
source paths and declared dependency grants. It includes its own source file.
Regenerate it when adding/removing source files or changing package dependencies.
`project.ts` supplies the same build request to Node and native execution, including
runtime roots, authorized host leaves, and initial memory policy. Its exported
`runtimeSources()` lists explicit provider module/namespace pairs in stable order;
tooling can share those contracts without deriving paths from namespace labels.

The CLI uses the finite native filesystem/process adapters and standard UTF-8
globals. Core compilation and artifact construction do not depend on this CLI.
Self-hosting requires the resulting executable to rebuild these same sources and
then execute the rebuilt compiler; successful Node emission alone is insufficient.

The current compiler project provides 1 GiB of managed payload and 16,777,216
allocation descriptors, with collector workspaces sized to that descriptor budget.
These are independent limits: the earlier 2,097,152-descriptor policy exhausted
its slots with roughly 105 MB allocated during specialization despite abundant
free payload space. Collector/control mappings are separate from managed payload.
The project adapter owns this policy; core compiler modules do not set it.
