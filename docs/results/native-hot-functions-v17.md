J’s three bounded diagnostics use the same 1,000 distinct eval source (SHA-256 `79a1792e31612125d20c1eedb3dc926c7289b526c7f25b3ea234b1312fcd0fca`), but different frozen compiler graphs; they are not an isolated P comparison. They reach the initial stop and time out within 65 wall seconds, with no verified exit 42. Their early windows and 20-second windows are different phases. No RegExp matching appears on these reported stacks. The original unchanged RegExp literal receives 284.09 CPU seconds near its 300-second timeout, establishing real native slowness. Compiler initialization is cached once, so directory reconstruction is not attributed to every eval.

The direct condition-carrier slice is already on main. Field forwarding improves the operation loop by 1.38x but is held after a +16.4% whole-compiler instruction regression. Conservative late scheduling removes that displacement but cannot reach the program module after its existing budget is consumed. The next local codegen route is to reuse identities in existing per-function access/SSA analysis, rather than add a global phase. The larger alternatives are origin-aware dense arrays inside managed images and immutable AOT metadata tables for first-eval preparation. Both need representation/ABI design and proof. Expected type checking, graph traversal and hashing alone are not optimization findings. J's Node OOM on 64-variant property batches remains compile-side context.
