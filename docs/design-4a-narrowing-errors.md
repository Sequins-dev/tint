This draft covers the narrowing and error portions of [slice 4a](unified-pipeline.md#migration-slices) at source revision `eb1d822db89f747d0ad9a76d8400352704e8732c`.

General source functions, built-ins and generated trusted export adapters are `OrdinaryObject` records with an `internalCall` field holding the native implementation. Ordinary noncallables use the same object factory with no call implementation. Proxy creation preserves callable capability independently of the handler and revocation state. The callable record is the object containing the implementation. Comparing its header to the native implementation's closure descriptor cannot classify it. Existing general `objectValueTypeof` already checks BigInt, Symbol, HTMLDDA and `isCallableObject`, and uses raw typed `typeof` as its fallback. See `packages/js-runtime/src/objects/operations.ts:289–298,329–404`, `call.ts:3–7`, `proxy.ts:269`, `functions.ts:381–412`, `values.ts:97–107` and `packages/js-engine/src/program/index.ts:232–253`.

Typed `TypeError` and `RangeError` are reference kinds (`packages/ts-native/src/closure/lowering/records.ts:499–512`). `error-new` allocates a private header plus a message pointer. `error-is` tests the exact private descriptor of the category-5 payload. Realm errors instead have ordinary object identity, `internalErrorData` and a prototype chain from `createErrorRealm`. `createRuntimeError` and the installed constructors use that chain, with TypeError and RangeError prototypes inheriting from Error.prototype. There is no shared object layout or prototype between the two systems. The trusted adapter returns or passes `unknown` unchanged and does not turn one error into the other. See `packages/codegen/src/aarch64/scalar/index.ts:8952–9016`, `packages/js-runtime/src/objects/errors.ts:315–346,680–691,714–740,832–919,941–948` and `packages/js-engine/src/program/index.ts:232–253,521–525`.

I ran pinned TypeScript 6.0.3 with `strict`, `noUncheckedIndexedAccess` and ES2022 libs, and probed Tint with `checkClosureModule`. An offline dependency install and `pnpm build` exited 0. A throwaway `TINT_BUILD_ONLY=1 TZ=UTC` hosted program used a general caller and three trusted typed functions. Its four baseline checks were that the typed classifier says `"object"` for a JS arrow, typed `instanceof RangeError` is false for a realm RangeError, typed `instanceof RangeError` is true for a typed RangeError, and both general `instanceof RangeError` and `instanceof Error` are false for that same typed value. The build reported general fallback for the application (`link: unknown value name: Error`). LLDB stopped at entry and exited 42, with `STATE True 42`. The build manifest records image SHA-256 `e852256cf54032ee2708c74834160504c0f1f2e34545c7603bafa105155c8837` and application fixture SHA-256 `ce9a2890c216fd7c9fb9e1a1af982aa3fa40d25ef4e064e5802b5708898cf494`. Implementation gates apply to the future change.

## Shared runtime wiring

Extract the lazy program-realm creation from the generated host at `packages/js-engine/src/program/index.ts:555–590,605–625`. Put the shared state and operations under `packages/js-runtime/src`, with a small public typed-operations entrypoint. Its realm state owns the global object, global environment, agent, symbol registry and hooks. Both typed-only compilation and the generated general host resolve the same runtime module ID and module instance. The general host configures its module loader and console on it. Publish the realm core before installing groups and install each selected group once. Intrinsic dependencies and ordering must be decided before the first user initializer can observe globals. An installer must never run again after JS has replaced a constructor.

Integrate the helper provider in `packages/compiler/src/project.ts` and typed linking in `packages/compiler/src/native/index.ts`. Factor the representation-view bindings from `createGeneralLowering` in `packages/js-engine/src/program/index.ts:46–81` into the common composition path. The typed attempt precedes general fallback, and only the fallback currently attaches those bindings (`packages/compiler/src/native/index.ts:558–615,660–679`). Extend the checked runtime demand/planning path to retain only used typed operations and the installer groups they need. In mixed builds take the union of checked typed demands and the groups selected by `generalIntrinsics` (`packages/js-engine/src/program/intrinsics.ts:106–145`). Link using canonical source IDs. Collect candidate features from bound source references and exception-producing operations, then let checker and lowering facts determine which helpers are retained. Include trusted modules and retained runtime dependencies in the demand calculation. Apply installer dependencies before evaluation, including Function intrinsics for inherited Symbol.hasInstance and ArrayBuffer intrinsics for typed arrays. An image built to accept general values from another image must keep the general classification path even if its own source constructs no realm objects. Keep the shared runtime below the compiler and general rewriter in the dependency graph. Wire the current CLI/project and hosted composition so `requireTyped` works without a general rewriter. Update package references, workspace contracts and the generated compiler catalog if a dependency changes.

In `packages/typescript/src/checker/index.ts` and `closures.ts`, record the semantic operation and type separately from storage. In `packages/ts-native/src/closure/lowering/index.ts`, `records.ts` and `runtime/{index,function-ids}.ts`, resolve the operation to a validated helper ID/signature. Use ordinary scalar calls in `scalar.ts`, boxing arguments once with existing general coercions and projecting only with proof or an explicit contract. Use a small helper surface with general signatures: classify `(value: unknown): string`, instance test `(value: unknown, target: unknown): boolean`, property get and has `(value: unknown, key: string): unknown` and `: boolean` respectively, call `(callee: unknown, receiver: unknown, args: readonly unknown[]): unknown`, construct `(target: unknown, args: readonly unknown[]): unknown`, and intrinsic error creation `(kind: string, message: string | undefined): unknown`. Reuse the ScriptPropertyKey entrypoints for computed symbol keys. The facade unwraps ordinary runtime completion records and throws their realm error on failure. Runtime object views use the existing descriptor-tested record bindings (`packages/ts-native/src/closure/lowering/record-bindings.ts:125–153`). The first implementation requires no new scalar opcodes or value tags. Leave the `general-kind`, `error-new` and `error-is` codec entries and round-trip samples intact while migrating producers. Add lowering tests for helper target, result ABI, exception successors, and the absence of legacy error IR on migrated paths. A later deletion must update the model, scalar effects, operands, substitution, call targets, AArch64 validation/emission and the storage kind table/samples (`packages/ir/src/storage/codec.ts:327,541–546,830,1054–1055`, `packages/ir/test/function-store.test.ts:50,158–159,330–337`). Reserve removed opcode numbers.

## `typeof` and callable values

Use the existing `objectValueTypeof` decision in tiered lowering. Keep `general-kind` as the raw representation operator, including its native-function descriptor check. In programs with realm values, use the descriptor-checked `OrdinaryObject` view to get to HTMLDDA and `internalCall`. Use the existing Symbol/BigInt views before falling back to raw classification. Mark the classifier fallback as a trusted raw-kind checker intrinsic, lowered straight to existing `general-kind`. Restrict that use to the runtime provider and internal representation checks so the helper cannot recursively lower to itself. No image-local descriptor or record field offset should escape into source-level code. A realm pointer is only needed by operations that use realm state. For the classifier, prefer the one-argument checked record-view form already recognized by `packages/ts-native/src/closure/lowering/index.ts:3254–3270` over forcing realm initialization to obtain a witness. Preserve typed fast paths when the compiler can prove no realm object can arrive. Compare against the `typeof` table and IsCallable, including callable classes, bound functions, and callable revoked proxies. Classification does not execute a trap or an accessor. [ECMAScript typeof](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-typeof-operator) · [IsCallable](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-iscallable)

Extend `refineLiteralBinding` to produce realm callable, symbol and object facts. For `"object"`, include null until a null guard rules it out. Retain `unknown` in a complement it cannot represent. Filter known unions and preserve existing concrete function signatures. Cover equality in either operand order, negation, short-circuiting and early exit, and reuse assignment/call invalidation at `packages/typescript/src/checker/closures.ts:814–884,2189–2231`. The callable fact maps to general storage and represents TypeScript's `Function`, whose direct call permits arbitrary arguments and has an `any` result. It does not gain a specific call or construct signature. Pinned `tsc` accepted `const s: string = x(1, "a")` after the guard and rejected both an unguarded `x()` and assigning the guarded `x` to `(n: number) => string`. Preserve that acceptance by keeping a general dynamic result, coercing at explicitly typed consumption through the existing checked projection machinery. Inferred results stay open. Operations on that result use general semantics. Any operation outside the supported general lowering must diagnose the unsupported construct explicitly.

Lower a direct call through `callObjectValue` in `packages/js-runtime/src/objects/values.ts:131–143` with receiver `undefined`, or through the property-reference path retaining the receiver for a member call. Evaluate callee and arguments once in source order. Propagate abrupt completions and convert the call helper's type failure to a realm TypeError. A class passes `typeof` and throws when called without `new`. For a native typed closure entering a general call path, generate an identity-preserving callable view with an adapter for the original signature, using the checked-entry pattern in `packages/js-engine/src/program/index.ts:232–253,521–552`. Box results and check explicitly annotated arguments when entering the typed target. Keep the existing direct typed path when the concrete signature is known. For a source-created closure, allocate the view at the escape-capable creation site and thread that same value through captures, aliases and joins. Existing opaque closures from managed/native ABIs require the slice 2b closure view before they can cross. Diagnose an unadaptable crossing during lowering instead of calling a raw word pointer with a guessed ABI. [EvaluateCall](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-evaluatecall) · [ECMAScript function call](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-ecmascript-function-objects-call-thisargument-argumentslist)

## `instanceof`: realm constructor lookup and flow

Resolve unshadowed realm built-ins as ordinary global lookups against the shared realm. Add constructor types and instance relations in `checker/interfaces.ts` and `types/index.ts`. Carry construct signatures through aliases and ordinary member expressions. Choose narrowing facts from the checked RHS type, including the type-predicate result of a declared `[Symbol.hasInstance]` where available. A shadowing binding uses its own signature and identity. Model `unknown instanceof Uint8Array`, `unknown instanceof Error`, `unknown instanceof C` for `C: ErrorConstructor`, and other installed realm constructors through the same operation. Pinned TypeScript accepts these and rejects `42 instanceof Error`. Reject an invalid static RHS under TypeScript's construct/call/hook rules. Static rejection still leaves ECMAScript's runtime failure behavior for operands arriving through dynamic inputs.

Lower the predicate to `instanceOfValue` (`packages/js-runtime/src/objects/functions.ts:450–510`). Evaluate the LHS then RHS exactly once. Get and invoke Symbol.hasInstance before requiring a callable default RHS. Keep bound-target delegation, the primitive LHS rule for the ordinary fallback, actual prototype traversal and its proxy traps (`packages/js-runtime/src/objects/operations.ts:720–729`), and abrupt completion. A successful branch refines the source binding or stable access path, using the existing fact set. False branches exclude only known union constituents TypeScript would exclude. Neither branch changes storage or creates a contract. Property/method uses of the refined value operate on the original object, with an independent representation proof required for specialization. A changed global constructor, a custom hook returning true, or an ordinary object created with a typed-array prototype can produce a valid positive result without native array storage. [InstanceofOperator](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-instanceofoperator) · [OrdinaryHasInstance](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-ordinaryhasinstance)

For typed arrays, carry the same static kind with either native-proven storage or realm-general storage in the representation plan. Realm arrays already use an integer-indexed object and `internalTypedArrayData` (kind, buffer and window), with brand checks for prototype methods. Lower bracket reads/writes through realm Get/Set, metadata through ordinary property access, and methods through lookup and call. This covers length, buffer, byteLength, byteOffset, indexing, set, slice and subarray without projecting the payload or copying bytes. It also works for realm kinds that lack a native scalar representation, including signed, clamped, floating-point and BigInt element kinds, using the installed constructor/type declarations and element kinds. See `packages/js-runtime/src/objects/typed-array-{data,construction,intrinsics}.ts:51,74,120` respectively for the lookup, source processing and receiver checks, and `typed-array-data.ts:185–219` for allocation. With `noUncheckedIndexedAccess`, `x[0] ?? 0` can yield a number while assigning `x[0]` directly to `number` is rejected for Uint8Array.

Plan storage before scalar lowering. Mark producers/consumers connected through assignment, joins, captures and typed calls/returns to a realm observation, including boxing to `unknown` that can reach one. Use a general-capable signature for those parameters/results, independent of the static array type. Select realm construction at observed source allocation sites, including cases where a native optimization cannot preserve replaceable globals or prototype behavior. Leave proven native-only allocations and private byte storage on the existing scalar path. A join loses the storage proof unless every predecessor proves it. A narrowed array must be usable by another typed helper, so the representation plan needs to cross function boundaries and handle indirect signatures conservatively. For an externally supplied native-only array, use the identity-preserving slice 2b buffer/view bridge before observation. Treat that bridge as a dependency for fixed native ABIs rather than adding a clone or a second object identity. The current marker-based Uint8Array downcast can remain for native-proven values; any realm-array contract must validate the declared type separately from the storage projection. Test real, forged, proxy, subclass, detached and out-of-range cases. [Integer-indexed exotic objects](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-integer-indexed-exotic-objects) · [TypedArray intrinsic](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-typedarray-objects)

## Realm Error, property reads and coded errors

Model `Error`, its native subtypes and their call/construct signatures using the pinned declarations. TypeScript accepts `new Error()`, `new Error(undefined, { cause: 42 })`, `TypeError("x")`, subtype-to-Error assignment, and `name: string`, `message: string`, `stack?: string` reads after a guard. The ES2022 declarations add `cause?: unknown`. TypeScript rejects `new Error(1)` even though JavaScript coerces the message, and rejects `e.code` on plain Error. See `node_modules/typescript/lib/lib.es5.d.ts:1073–1082` and `lib.es2022.error.d.ts:19–31` in the pinned installation.

Represent a typed Error and its subtypes as general values. Explicit source calls and constructors use normal global lookup and the installed call or construct operation, honoring shadowing and newTarget with the existing default and inherited properties. Unify internal source-visible error creation (`checkedDowncast` and `requireCondition` at `packages/ts-native/src/scalar.ts:2268–2332`, source constructors at `3677–3703`, other producers found by auditing exception paths) through a realm factory that accepts an intrinsic kind and optional message. Compiler-generated and host validation failures use the intrinsic even after JS replaces the global. Extract message installation from `installErrorIntrinsics` so both paths share `errorFromPrototype` and its descriptor rules. Keep engine aborts and stack-overflow translation on their existing paths (`packages/js-runtime/src/objects/errors.ts:786–818`). Avoid catch-time reboxing. Throw, catch, rethrow and mixed-boundary passing preserve identity and the exception channel. Retain private error opcodes only as transitional/internal machinery while observable producers migrate. An observable TypeError or RangeError may never escape as a private descriptor in the completed paths. [Error constructor](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-error-message) · [InstallErrorCause](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-installerrorcause)

Box the message and options normally. A typed options record that escapes into the constructor uses the existing 2b record view so the cause lookup observes the original object and its accessors. Use ordinary `getObjectValueProperty`/Set for Error properties. Preserve own and inherited descriptors, getter receiver, changes to the prototype and original throws. Missing message inherits the empty string; a supplied message becomes an own non-enumerable property. Stack follows existing Tint realm behavior, the accessor and execution-name snapshot in `packages/js-runtime/src/objects/errors.ts:714–740,983–1031`. The design commits to the shared realm's stack behavior and optional string type, without V8 formatting or a native stack walk. A fake or mutated Error may have absent or foreign values. Keep unspecialized operations general and check at written contracts before unboxing or committing the write. Error annotations use the declared structural interface (TypeScript accepts `{name:"Custom", message:"text"}` as Error), with checks for required members and present optional members at a dynamic crossing. Prototype identity belongs to `instanceof` and `[[ErrorData]]` to the Error brand. Neither substitutes for a structural slot check. Reuse the cast/contract machinery and realm Get, preserve identity and test observed accessor order. A property statically described by a type does not impose an annotation on someone else's open JS object.

Add literal-key `in` checking and flow facts for known objects in `closures.ts`, plus the realm HasProperty helper using the existing operation in `packages/js-runtime/src/objects/operations.ts:732–743`. After `if (e instanceof Error && "code" in e && typeof e.code === "string")`, read `e.code` as string. The first property fact is `unknown` and a subsequent typeof or value test refines it. Lower all property reads in source order, including fresh getter invocations. Preserve Proxy has/get and inherited properties. A mutation or repeat getter can invalidate the representation proof even while TypeScript keeps the static fact. Only use an unboxed value when the specific read is proven or checked. A local `const code = e.code` provides a stable binding for repeated typed uses. Apply the same pattern to errno/syscall. Producers may publish explicit structural interfaces for coded and system errors. Keep the built-in Error interface free of these fields. [Relational operators and in](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-relational-operators)

Put Node error factories in a Node-specific runtime module outside FFI internals. Have the factories make real realm errors from the intrinsic kind, then install public properties using ordinary descriptor operations. For plain zlib-style or crypto coded errors, use writable, enumerable, configurable own data properties, with insertion order matching the Node producer. For SystemError, create one realm-local SystemError prototype inheriting from Error.prototype and use the message/stack allocator with this prototype. For the OS calls in scope, define own non-enumerable writable name and message, enumerable `code = "ERR_SYSTEM_ERROR"`, enumerable `info`, and own enumerable/configurable `errno` and `syscall` accessors aliasing that same info record. The info fields retain the platform UV error details. Node's private brand and V8 stack tooling are out of scope. No JavaScript global SystemError constructor is required. [Node v24.12.0 SystemError](https://github.com/nodejs/node/blob/v24.12.0/lib/internal/errors.js#L253-L326)

- The type/representation split matters most at joins, public ABIs, dynamic receiver mutation and implicit exception edges. Test installed groups before module evaluation, and check for duplicated realm state by strict identity from both paths. Compare emitted IR for unchanged bootstrap sources. Compiler dependencies already construct native errors (`packages/foundation/src/text/text-encoding/index.ts:232,245`), and checked cast/guard changes affect existing lowering. - Measure minimal typed binaries with no realm feature, Error only, array/instanceof and mixed imports. The coarse general core can be expensive (slice 1c estimate at `docs/unified-pipeline.md:339`). Keep installer registration demand-driven. Inspect linked symbols and cold failure-path reachability before considering installer splitting. Avoid regenerating the same operation/call adapter per site when the signature and target are shared.
- These steps require no work in image writers/layout, startup, build/image-writer/spill-files, collector or stack maps, or FFI internals.
