This proposal covers the narrowing and error portions of [slice 4a](unified-pipeline.md#migration-slices) at source revision `eb1d822db89f747d0ad9a76d8400352704e8732c`.

General source functions, built-ins and generated trusted export adapters are `OrdinaryObject` records with an `internalCall` field holding the native implementation. Ordinary noncallables use the same object factory with no call implementation. Proxy creation preserves callable capability independently of the handler and revocation state. The callable record is the object containing the implementation. Comparing its header to the native implementation's closure descriptor cannot classify it. Existing general `objectValueTypeof` already checks BigInt, Symbol, HTMLDDA and `isCallableObject`, and uses raw typed `typeof` as its fallback. See `packages/js-runtime/src/objects/operations.ts:289–298,329–404`, `call.ts:3–7`, `proxy.ts:269`, `functions.ts:381–412`, `values.ts:97–107` and `packages/js-engine/src/program/index.ts:232–253`.

Typed `TypeError` and `RangeError` are reference kinds (`packages/ts-native/src/closure/lowering/records.ts:499–512`). `error-new` allocates a private header plus a message pointer. `error-is` tests the exact private descriptor of the category-5 payload. Realm errors instead have ordinary object identity, `internalErrorData` and a prototype chain from `createErrorRealm`. `createRuntimeError` and the installed constructors use that chain, with TypeError and RangeError prototypes inheriting from Error.prototype. There is no shared object layout or prototype between the two systems. The trusted adapter returns or passes `unknown` unchanged and does not turn one error into the other. See `packages/codegen/src/aarch64/scalar/index.ts:8952–9016`, `packages/js-runtime/src/objects/errors.ts:315–346,680–691,714–740,832–919,941–948` and `packages/js-engine/src/program/index.ts:232–253,521–525`.

I ran pinned TypeScript 6.0.3 with `strict`, `noUncheckedIndexedAccess` and ES2022 libs, and probed Tint with `checkClosureModule`. An offline dependency install and `pnpm build` exited 0. A throwaway `TINT_BUILD_ONLY=1 TZ=UTC` hosted program used a general caller and three trusted typed functions. Its four baseline checks were that the typed classifier says `"object"` for a JS arrow, typed `instanceof RangeError` is false for a realm RangeError, typed `instanceof RangeError` is true for a typed RangeError, and both general `instanceof RangeError` and `instanceof Error` are false for that same typed value. The build reported general fallback for the application (`link: unknown value name: Error`). LLDB stopped at entry and exited 42, with `STATE True 42`. The build manifest records image SHA-256 `e852256cf54032ee2708c74834160504c0f1f2e34545c7603bafa105155c8837` and application fixture SHA-256 `ce9a2890c216fd7c9fb9e1a1af982aa3fa40d25ef4e064e5802b5708898cf494`. Implementation gates apply to the future change.

## Demand-driven runtime wiring

Keep the existing typed attempt and attach realm capabilities when the compile request can contain realm values. Today the mixed fallback supplies checked view bindings and retained runtime exports, while the typed attempt and the compiler self-build use their own requests. Reuse that seam for classification and later realm operations. A future typed-only use of a realm feature can explicitly request those capabilities at the composition root. It shares the program realm from the generated host, with canonical module identity, dependency-ordered installers and one installation before user initialization. Native errors and guards are independent of this demand. The roughly 27 MB realm-core cost makes this distinction significant even when exceptions are cold. See `packages/compiler/src/native/index.ts:558–615,660–679`, `packages/js-engine/src/program/index.ts:46–81,555–625`, `packages/js-engine/src/program/intrinsics.ts:106–145` and `docs/unified-pipeline.md:116–152,449–459`.

Keep static flow facts separate from representation. Resolve optional realm helpers by checked function identity and validate their parameter and result representations at closure lowering. Use ordinary scalar calls over the existing two-word general ABI with compiler-managed exception edges. A view projects only after a descriptor test. Property and call operations receive the original value and use the shared realm's normal completion handling. Reuse ScriptPropertyKey for computed keys and preserve receiver identity and evaluation order. New module registrations, if needed, also require workspace references and a regenerated compiler catalog. See `packages/typescript/src/checker/index.ts:48–80`, `packages/ts-native/src/closure/lowering/index.ts:845–893,3254–3270`, `packages/ts-native/src/scalar.ts:2672–2706` and `AGENTS.md:26–35`.

## `typeof` and callable values

Use the existing `objectValueTypeof` decisions in mixed lowering. Resolve a one-argument helper by the mixed program's checked runtime binding. It uses descriptor-checked Symbol, BigInt and OrdinaryObject views, then checks HTMLDDA and the internal call capability. It needs no realm pointer or installer. Its fallback is raw typed `typeof`. Mixed lowering selects the semantic classifier by checked helper identity in original typed source modules. Generated general modules already emit semantic operations, and the general runtime’s implementation modules keep raw representation tests, including in the classifier itself. Outside this capability, retain the existing BigInt and `general-kind` lowering, including its native closure descriptor check. A revoked proxy retains its original call capability. Neither reading that capability nor classifying primitives executes JavaScript. See `packages/js-runtime/src/objects/values.ts:69–107`, `packages/js-runtime/src/objects/call.ts:3–7`, `packages/js-runtime/src/objects/proxy.ts:269`, `packages/ts-native/src/scalar.ts:4244–4292` and `packages/codegen/src/aarch64/scalar/index.ts:8733–8787`. [ECMAScript typeof](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-typeof-operator) · [IsCallable](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-iscallable)

Extend `refineLiteralBinding` to produce realm callable, symbol and object facts. For `"object"`, include null until a null guard rules it out. Retain `unknown` in a complement it cannot represent. Filter known unions and preserve existing concrete function signatures. Cover equality in either operand order, negation, short-circuiting and early exit, and reuse assignment/call invalidation at `packages/typescript/src/checker/closures.ts:814–884,2189–2231`. The callable fact maps to general storage and represents TypeScript's `Function`, whose direct call permits arbitrary arguments and has an `any` result. It does not gain a specific call or construct signature. Pinned `tsc` accepted `const s: string = x(1, "a")` after the guard and rejected both an unguarded `x()` and assigning the guarded `x` to `(n: number) => string`. Preserve that acceptance by keeping a general dynamic result, coercing at explicitly typed consumption through the existing checked projection machinery. Inferred results stay open. Operations on that result use general semantics. Any operation outside the supported general lowering must diagnose the unsupported construct explicitly.

Lower a direct narrowed `Function` call through `callObjectValue` with receiver `undefined`. A property reference retains its receiver. Evaluate the callee and each argument once, left to right, before testing and invoking the callable. Preserve abrupt completion, and let the ordinary class call path throw its TypeError. For a native closure through this dynamic path, diagnose a statically proven case during lowering or throw TypeError after argument evaluation when the representation is only known at run time. Use the message `Calling a native closure through Function requires the slice 2b closure view`. A known concrete typed signature still uses the existing direct or indirect typed path. Record the dynamic call limitation in the gap table. See `packages/js-runtime/src/objects/values.ts:131–143`, `packages/ts-native/src/scalar.ts:2672–2706` and `docs/unified-pipeline.md:265–275`. [EvaluateCall](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-evaluatecall)

## `instanceof`: realm constructor lookup and flow

Resolve unshadowed realm built-ins as ordinary global lookups against the shared realm. Add constructor types and instance relations in `checker/interfaces.ts` and `types/index.ts`. Carry construct signatures through aliases and ordinary member expressions. Choose narrowing facts from the checked RHS type, including the type-predicate result of a declared `[Symbol.hasInstance]` where available. A shadowing binding uses its own signature and identity. Model `unknown instanceof Uint8Array`, `unknown instanceof Error`, `unknown instanceof C` for `C: ErrorConstructor`, and other installed realm constructors through the same operation. Pinned TypeScript accepts these and rejects `42 instanceof Error`. Reject an invalid static RHS under TypeScript's construct/call/hook rules. Static rejection still leaves ECMAScript's runtime failure behavior for operands arriving through dynamic inputs.

Lower the predicate to `instanceOfValue` (`packages/js-runtime/src/objects/functions.ts:450–510`). Evaluate the LHS then RHS exactly once. Get and invoke Symbol.hasInstance before requiring a callable default RHS. Keep bound-target delegation, the primitive LHS rule for the ordinary fallback, actual prototype traversal and its proxy traps (`packages/js-runtime/src/objects/operations.ts:720–729`), and abrupt completion. A successful branch refines the source binding or stable access path, using the existing fact set. False branches exclude only known union constituents TypeScript would exclude. Neither branch changes storage or creates a contract. Property/method uses of the refined value operate on the original object, with an independent representation proof required for specialization. A changed global constructor, a custom hook returning true, or an ordinary object created with a typed-array prototype can produce a valid positive result without native array storage. [InstanceofOperator](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-instanceofoperator) · [OrdinaryHasInstance](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-ordinaryhasinstance)

A typed-array instanceof guard refines the static kind while retaining the original general value. For indexed reads and writes, metadata and methods, test storage at the use site using the existing native typed-array header tests and their supported-kind siblings. Take the native path for matching storage. Otherwise use realm Get/Set and method lookup/call when the program can contain realm values. Typed-only programs use native operations and native errors if a receiver lacks compatible storage. Realm arrays store the kind, buffer and window in their integer-indexed object. A spoofed prototype or overriding hasInstance can therefore pass the guard while a brand-checked method still throws. Keep the TypeScript unchecked-index policy on both paths. See `packages/ts-native/src/closure/lowering/index.ts:2663–2710`, `packages/codegen/src/aarch64/scalar/index.ts:8664–8730,9040–9084`, `packages/js-runtime/src/objects/typed-array-data.ts:51,185–219`, `packages/js-runtime/src/objects/typed-array-intrinsics.ts:120` and `docs/unified-pipeline.md:393–405`.

An argument to an existing native `Uint8Array` parameter takes the same checked projection as `unknown as Uint8Array`. Matching native storage passes without copying. A realm-only array throws TypeError with `Passing a realm typed array to a native typed-array parameter requires the slice 2b buffer view`. Apply the same rule to sibling native ABIs. Keep this limit in the gap table until a view can share the buffer and preserve identity. Realm-only typed-array kinds operate through the realm. The guard leaves local storage and all function signatures as they were. See `packages/ts-native/src/scalar.ts:2268–2332`, `packages/codegen/src/aarch64/scalar/index.ts:9040–9084` and `docs/unified-pipeline.md:265–275`. [Integer-indexed exotic objects](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-integer-indexed-exotic-objects)

## Native errors and their realm views

Add a native Error kind and preserve the existing TypeError and RangeError descriptors, `error-new` and `error-is` forms and message storage for unchanged typed-only programs. Native `instanceof Error` accepts all three intrinsic kinds. Specific subtype checks accept only the matching kind. Add `new Error(message)`, the Error annotation, flow facts for error guards and native `message`, `name` and `stack` reads. Native message defaults to the empty string and name to the intrinsic name. Native `stack` is `undefined` until native stack capture exists, consistent with TypeScript's optional string. Preserve existing compiler contract error emission through `requireCondition` and `checkedDowncast`. Reject an options argument on the native constructor with `Error options (cause) require the realm Error constructor`. This defers observable HasProperty/Get of arbitrary options to the existing realm constructor. An options argument must never be dropped silently. See `packages/ts-native/src/scalar.ts:2268–2332,3677–3703`, `packages/codegen/src/aarch64/scalar/index.ts:8952–9016` and TypeScript 6.0.3 `node_modules/typescript/lib/lib.es5.d.ts:1073–1082`, `lib.es2022.error.d.ts:19–31`. [InstallErrorCause](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-installerrorcause)

At a realm entry, including a return or exception escaping a trusted call, convert a native error to an ordinary realm error view. Do this also at later mixed operations that first expose a native error to realm code. Use the slice 2b per-object traced view slot for native error layouts in realm-capable images, with a reciprocal traced native reference on the realm object where projection needs it. Publish the view once per native identity with the appropriate intrinsic prototype from the same program realm. Reuse the view on every exposure, including after rethrow, aliasing and a round trip through typed code. `Object.getPrototypeOf(e) === TypeError.prototype` holds for an unmodified intrinsic and its matching error. Realm `instanceof` follows actual prototypes and Symbol.hasInstance. Install `[[ErrorData]]` so default `Object.prototype.toString.call(e)` yields `"[object Error]"`, subject to ordinary Symbol.toStringTag overrides. Reuse the realm error allocation and message descriptors. Capture the realm execution-name snapshot when an error is created in a realm-capable image, for later stack access even after unwinding, without allocating the view at the throw site. A realm read, mutation, deletion or prototype change uses the view's own ordinary properties and current prototype. See `docs/unified-pipeline.md:237–275`, `packages/js-engine/src/program/index.ts:232–253,521–552`, `packages/js-runtime/src/objects/errors.ts:315–346,680–740,983–1031` and `packages/js-runtime/src/objects/functions.ts:450–510`. [Object.prototype.toString](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-object.prototype.tostring)

On the typed side dispatch by representation. A native descriptor with no published view uses native fields and kind checks. A realm object, including a previously exposed native error, uses ordinary realm Get/instanceOf for all observable operations so changes through the view remain visible. Preserve the canonical representation in mixed identity comparisons when native and realm aliases meet. Keep ordinary throw, catch and rethrow on the existing exception channel. A structural Error slot tests required members and optional members when present at a dynamic crossing. Accessor effects occur in source order and the value retains its identity. Static structural acceptance (for example `{ name: "Custom", message: "text" }`) is distinct from `instanceof` and from the internal Error brand. Native-only layouts gain no per-object cache or realm references. See `docs/unified-pipeline.md:154–193,237–275`, `packages/js-runtime/src/objects/operations.ts:720–743`, `packages/js-runtime/src/objects/functions.ts:450–510` and `packages/codegen/src/aarch64/scalar/index.ts:8952–9016`.

Add literal-key `in` checking and flow facts for known objects in `closures.ts`, plus the realm HasProperty helper using the existing operation in `packages/js-runtime/src/objects/operations.ts:732–743`. After `if (e instanceof Error && "code" in e && typeof e.code === "string")`, read `e.code` as string. The first property fact is `unknown` and a subsequent typeof or value test refines it. Lower all property reads in source order, including fresh getter invocations. Preserve Proxy has/get and inherited properties. A mutation or repeat getter can invalidate the representation proof even while TypeScript keeps the static fact. Only use an unboxed value when the specific read is proven or checked. A local `const code = e.code` provides a stable binding for repeated typed uses. Apply the same pattern to errno/syscall. Producers may publish explicit structural interfaces for coded and system errors. Keep the built-in Error interface free of these fields. [Relational operators and in](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-relational-operators)

Put Node error factories in a Node-specific runtime module. Use native coded Error and RangeError descriptors with presence and typed storage for the producer's own fields. Use a SystemError record with native info storage for the platform details and make typed `errno` and `syscall` alias that info. This keeps typed Node failures independent of the realm. Native `"code" in e` uses the presence or layout fact, including absence for ordinary Error, and checks receiver validity before consulting the property. Once a view exists, use realm HasProperty so inherited, deleted, reconfigured and proxy-observed keys behave normally. See `packages/codegen/src/aarch64/scalar/index.ts:8952–9016`, `packages/js-runtime/src/objects/operations.ts:732–743` and the existing producers below.

Populate the same cached view with Node's public own-property shapes at the boundary. Plain zlib and crypto coded fields are writable, enumerable and configurable in the producer's insertion order. SystemError uses one realm-local prototype inheriting from Error.prototype, own non-enumerable writable name and message, enumerable `code = "ERR_SYSTEM_ERROR"` and `info`, and enumerable/configurable `errno` and `syscall` accessors aliasing that same info object. Use the shared error brand and stack machinery. Existing Node private branding and V8 stack tooling stay outside this scope. [Node v24.12.0 SystemError](https://github.com/nodejs/node/blob/v24.12.0/lib/internal/errors.js#L253-L326)

## Runtime workarounds and follow-up

- **Crypto.** The TypeError workaround is at `packages/native-runtime/src/node/crypto.ts:2–5,32–39,65–70`. Use a plain native Error for unsupported digest and a plain Error carrying `ERR_CRYPTO_HASH_FINALIZED` for repeated digest/update. Pinned Node confirmed both shapes, including absence of a code for the tested unrecognized algorithm. Keep the Hash class and ASCII case-folding defects tracked separately (`crypto.ts:28,77`). The digest encoding branch at `crypto.ts:53` needs its own behavior comparison. The Node probe returned a Buffer for the tested unknown encoding. [Node crypto hash](https://github.com/nodejs/node/blob/v24.12.0/lib/internal/crypto/hash.js)
- **Zlib.** Replace `failure` and the initialization throw (`packages/native-runtime/src/node/zlib.ts:15–18,98–102,184–196,207–227`) with native Error, status `errno` and matching `Z_*` code. Pass the status at the failure site. Normalize premature input exhaustion and missing dictionaries as Node does. Pinned Node confirmed truncated gzip `Z_BUF_ERROR/-5`, invalid compressed data `Z_DATA_ERROR/-3` and a missing dictionary `Z_NEED_DICT/2`. Use `ERR_OUT_OF_RANGE` for invalid ranges and `ERR_BUFFER_TOO_LARGE` for the output limit. Both were RangeErrors in the pinned Node probes (`zlib.ts:66–92,145–157,235–243`). Preserve stream cleanup and copies. [Node zlib error path](https://github.com/nodejs/node/blob/v24.12.0/lib/zlib.js#L174-L184)
- **OS.** Migrate `systemError` (`packages/native-runtime/src/node/os.ts:9–17,49–63`) to the SystemError factory and thread status at the OS adapter call sites. Test `userInfo()` with deterministic injected passwd failure and preserve EINTR/ERANGE control flow. Current passwd errors synthesize text and current interface-address failures default to EIO (`packages/native-runtime/src/node/os-darwin.ts:55–77,114–119`, `os-linux.ts:57–79,116–121`). For passwd, translate the available positive POSIX status to the UV errno/code/text and use the ENOENT mapping if no entry was found. Node v24.12.0 throws ERR_SYSTEM_ERROR from userInfo when the native call fails. Its networkInterfaces wrapper returns an empty object when the native binding yields undefined, and the C++ binding explicitly returns undefined for UV_ENOSYS. Do not automatically attach SystemError to Tint's interface-address workaround. Keep networkInterfaces failure parity tied to the existing plain-object return change and coordinate any new errno binding with the FFI owner. Dynamic-key and encoding limitations stay separate. [Node OS wrapper](https://github.com/nodejs/node/blob/v24.12.0/lib/os.js#L205-L209) · [Node userInfo and UV exception path](https://github.com/nodejs/node/blob/v24.12.0/src/node_os.cc#L279-L300) · [Node UV_ENOSYS handling](https://github.com/nodejs/node/blob/v24.12.0/src/node_os.cc#L182-L200)
- **Dynamic loader.** In an owner follow-up, replace `loaderError` and the dlsym diagnostic throw at `packages/native-runtime/src/ffi/dynamic.ts:700–746` with Error preserving `dlerror()` text and its read/clear order. Keep null-handle validation TypeErrors and the valid zero-address rule. Match any code at the public Node FFI wrapper against its chosen reference version. Bootstrap Node 24 precedes the Node FFI API, which the current upstream docs date to 26.1. This change is confined to the owner of the off-limits FFI tree. [Node FFI API](https://nodejs.org/api/ffi.html)
- After the corresponding checks pass, update the gap and workaround rows at `docs/unified-pipeline.md:360–389`, `docs/native-ffi.md:1461–1477` and the assertions that currently pin only the error kind. Leave the callback escape/safety workaround, C view gaps, unrelated option behavior and other slices tracked separately.
