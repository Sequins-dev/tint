# Framework consolidation

## Direction

Consolidate the original 94 packages into cohesive reusable frameworks with
explicit, narrow public entrypoints. Preserve internal modules and dependency
layers; package consolidation does not mean large files or an umbrella barrel.
The TypeScript frontend must support future TS-to-JS emission independently of
native lowering, runtime objects and platform code.

The workspace now has the fourteen framework owners below. Internal architecture
work remains incremental; package consolidation does not imply completion of all
future compiler capabilities. The ledger records captured workspace gates and
separate native verification evidence.

Foundation now owns binary, collections, graph, numeric, text, Unicode, layout,
RegExp syntax/matching and calendar/time algorithms through independent subpaths.
The latest layout/RegExp/chrono move preserves 33 implementation modules and
32 tests; its frozen source and smoke comparisons are recorded in the ledger.
Pure source-module metadata and request canonicalization also live in the independent
`foundation/modules` subpath. They carry no runtime object, realm or host state.
Host access and ECMAScript object adapters remain outside foundation.

Target startup emission now belongs to codegen. Platform owns concrete Darwin
policy; ABI owns its data contract. Mach-O serialization resolves addresses and
delegates target instruction patching through the relocation contract. Further
format-neutral link planning can evolve within image without recreating a host
package or introducing platform defaults into codegen.

Native intrinsic declarations now live under `native-runtime/intrinsics` for
memory, clocks, randomness, processes and files. Platform implementations and
portable facades remain separate entrypoints from those declarations.

The unused trace-plan, value-layout, gc-tracing and closure-tracing prototypes are
retired after caller auditing and production-contract test replacement; see the
[retirement audit](framework-prototype-retirement.md).
The legacy scalar checker must have its remaining fixtures migrated before it is
removed; native lowering's data types move to ts-native.

## Resolved ownership choices

- **Image versus platform:** image owns format serialization and the format-neutral
  link model. Platform owns OS services, startup selection and publication policy.
  AArch64 startup instructions belong to the target adapter. ISA-specific address
  patching now crosses the explicit relocation adapter rather than an image
  dependency on the instruction encoder.
- **ABI versus runtime:** ABI definitions have no allocator, collector, JavaScript
  object model or OS implementation dependencies. They describe realized wire
  formats; consumers retain emission, validation and authorization algorithms.
  Generic target-parameterized layout planning belongs to foundation/layout.
  Share descriptor constants/schemas between codegen and collectors instead of
  duplicating numeric layouts.
- **Script lowering:** js-engine owns the rewrite into runtime operations;
  ts-native owns the subsequent typed-source-to-IR lowering. TypeScript analysis
  and transpilation do not depend on js-runtime or js-engine.
- **Shared compiler pipeline:** compiler provides reusable compilation stages;
  js-engine composes them with its runtime. Compiler does not import js-engine.
  Future product composition roots must preserve this acyclic direction.
- **TS-to-JS output:** keep its path open through frontend/printer contracts, but
  create a ts-emit framework when its first implementation exists. Package moves
  alone do not provide ordinary generic checking, printing or declarations.

## Dependency and publication rules

1. Public framework subpaths are explicit manifest exports. A consumer declares
   the owning package dependency and imports only those exported subpaths.
   Relative imports stay inside the framework. No wildcard exports or root aliases.
2. Use narrow entrypoints for independent capabilities. Native runtime retention
   follows transitive module imports, so an umbrella barrel can pull unrelated
   code into a binary even when callers request one export.
3. Stable intrinsic/runtime contract IDs are independent of package/file names.
   Freeze these IDs before moving packages whose names currently identify helpers.
   Replace snapshot file-existence feature probes with explicit capabilities.
4. Keep the frontend independent of IR storage, runtime layouts, ISA and host
   policy. Semantic checking must ultimately precede native specialization;
   changing that order is a separate behavioral slice after the initial moves.
5. IR and target codegen do not import TypeScript syntax or JavaScript objects.
   JavaScript-specific operations and runtime bindings have explicit owners.
6. Frameworks may have layered internal modules and selective subpaths. Enforce
   package acyclicity and public imports throughout the transition; do not solve
   cycles with unchecked internal imports or compatibility packages.

## Migration sequence and gates

| Slice | Work                                                                                                                                         | Gate before proceeding                                                                                 |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| M0    | Explicit public subpath support in manifests, boundaries, catalog mappings, portable resolver and frozen-source tools                        | Positive/negative export-policy tests, actual graph resolution, existing workspace gates               |
| M1    | Move word64, bytes and SHA-256 into foundation's three narrow binary entrypoints; migrate all callers and delete old packages                | All tests/types/contracts, retained native algorithm fixtures, smoke output comparison and native exit |
| M2    | Stabilize builtin IDs, Script ABI imports, capability discovery and shared descriptor definitions                                            | Existing bindings remain identical; explicit mismatch rejection; native conformance comparison         |
| M3    | Consolidate remaining foundation/source components in independent slices                                                                     | Focused semantic/native tests and workspace gates per slice                                            |
| M4    | Consolidate frontend syntax/types/binding/checking while retaining existing behavior                                                         | Syntax gate and native self-hosting fixed point; no native dependencies introduced                     |
| M5    | Consolidate IR, target codegen and image layers independently                                                                                | IR/encoder/image tests, native smoke and same-snapshot stage-image comparison                          |
| M6    | Consolidate lowering, compiler, engine and runtime around the explicit contracts                                                             | Native regressions, frozen conformance selections and self-hosting                                     |
| M7    | Change architecture internally: semantic checking before specialization, representation passes, pass manager, machine IR/register allocation | Separate behavior-specific tests and native measurements per change                                    |

Each slice is a reviewable change with a frozen input and a complete result.
File/package moves and semantic changes are separate. Compare byte output across a
pure move when IDs/order/debug paths permit; retain and investigate differences.
Self-build fixed points compare stage1/stage2 within the same new snapshot, not
images from different source layouts. Preserve failed observations and source hashes.

Full Test262 runs retain their frozen toolchain and sources during migration.
Do not combine results across snapshots or silently disable moved features.
Native execution remains serialized through the existing cooperative checkpoints.
