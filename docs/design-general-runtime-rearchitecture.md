# General JavaScript runtime re-architecture proposal

## Route to parity (2026-11-23)

The landing bar is parity: PR #12 lands only when untyped code is at or faster than Node 26.13.1 on Octane (Richards, DeltaBlue, NavierStokes, RayTrace), the call/loop and generality kernels and the untyped builtin-call kernels. Steps 1, 2 and 2b (below the line, as originally proposed) brought the programs to 43–414× Node. The typed-path call/loop kernels already beat Node, so the typed pipeline is the quality bar the untyped path has to reach.

(RayTrace includes the inherited-writable-data transition fix, 3163021b0, measured in one rough run.) Even with every runtime cost removed, the generated code alone is 20–50× slower than Node's optimized code: 1.2 ms for Richards, 3.1 for DeltaBlue, 40 for NavierStokes, 13 for RayTrace. Cheaper runtime helpers cannot reach parity by themselves; the untyped path has to generate typed-quality code.

Total: about 10–18 weeks of one stream, with the uncertainty concentrated in steps 6 and 7. The order puts the largest measured shares first; each step keeps instruction budgets per operation (step 3: a warm method call ≤ 60 instructions with zero allocations) and the paired protocol for acceptance. Work that touches disjoint files can run in parallel: step 5's elements and builtin intrinsics alongside step 3's ABI, and an inference prototype for step 6 once step 3's entry convention is fixed.

### Activation records

Stack traces and the legacy `caller` and `arguments` accessors need to know which source functions are active. The register and list entry paths kept that in two heap chains (execution names and source-call frames), so every call wrote heap memory and paid remembered-set barriers (about 260 instructions per call). A native script entry instead links a 32-byte activation record into its own frame while it runs:

| Word | Contents |
| --- | --- |
| 0 | the previous record (0 at the base) |
| 8 | the frame pointer, with the kind in its low four bits: 1 when called with actual operands, 0 when called with a materialized list |
| 16, 24 | the callee's general pair (a stack-map root) |
| 32 | the actual operand count, followed by the register actuals; stack actuals follow the frame record |

The innermost record's address is a word of the hosted context (`nativeActivationTopOffset`). The entry's prologue links its record and its epilogue unlinks it on every return, normal or exceptional; exceptions return through the epilogue, so no unwinder is involved. The runtime reads records through `activation*` declarations in `js-runtime/src/objects/activations.ts`, bound to IR `activation-read` in native builds. The callee's register entry supplies its trace name and caller policy.

Heap frames remain for list entries, register entries, builtins and barriers. Each records the innermost native record at its push, so the readers merge both chains by stack position: a heap frame is younger than every record at or below the one it recorded. A list-mode record (kind 0) is skipped, because its heap frames already describe the call.

## Original proposal (2026-11-22)

Start with compact shapes, in-object fields and dense elements, then replace the ordinary call and construction ABI. For Richards, evaluate primitive comparison and binding lowering after layout work. Re-profile before expanding the allocation work. The Octane reports provide the source comparisons, hardware counts, executed instruction paths and cache census supporting this order. ## Phase 1 · Object storage, property handlers and elements

- Give ordinary objects a small shared shape and a compact header. Intern transitions on the prior shape, property key, attributes and field representation. Keep common constructor and literal fields at stable in-object offsets, with a contiguous spill area past those slots. Preserve insertion order, descriptors and stable identity on map transitions. Reserve the dictionary representation for dynamic or exotic cases. Make the first useful slice ordinary allocation plus an initial shape and a fixed field load/store through the same authoritative object storage.
- Attach a bounded set of data handlers to each eligible AOT property site. Each names a receiver shape, a slot and a guard for the holder when inherited. Start with one machine shape compare and a direct offset load/store. Add small polymorphic chains, prototype validity and bounded `(shape, name, operation)` megamorphic lookup. A miss stub resolves once and installs a handler, without reconstructing a parallel descriptor list on every new object. Use a small validity dependency for prototype changes and avoid retaining receivers through the cache.
- Handle holes, sparse transitions and non-default descriptors in a canonical element representation. For dense ordinary arrays and typed arrays, use a guarded element address and direct load/store inside the guest code, including widening from numeric to general storage. Preserve inherited numeric setters, typed-array detach/resize behavior, negative zero key handling and ordering around key coercion.
- **Scope.** `packages/js-runtime/src/objects/operations.ts` (`allocateObject`, `ordinaryGetOwnProperty`, `ordinaryDefineOwnProperty`, `lookupCachedScriptProperty`), `objects/array-elements.ts` and `objects/coercion.ts` (computed access), `packages/js-engine/src/lowering/index.ts` (`inlineCachedPropertyCell` and indexed read/write lowering), and the native layout/GC metadata consumed by those operations.
- **Cost and risk.** High. Shape invalidation errors can return stale methods or skip getters, proxy traps or typed annotations. The collector must distinguish tagged slots, raw numbers, transitions and weak dependencies. Benchmark constructor initialization and mutation as a pair with warm named loads, polymorphic stores and integer access. Record receiver bytes and managed allocations per new object, access latency, miss cost and invalidation. Check enumeration, descriptor changes, deletion, prototype replacement, getter and setter ordering, and managed contracts before widening the path.

## Phase 2 · Uniform native entry for calls and constructors

- Every ordinary compiled function should publish a common native entry, with a closure, receiver, `new.target`, argc, and general values passed in registers and then a known outgoing stack area. Have the callee supply undefined for missing parameters. Keep the actual area alive for over-application and observe it through stack maps. Emit an ordinary callee tag check and entry load at the call site. Use its native activation to derive caller, arguments and source trace state lazily. Change realm or Script state only when required, including correct restoration under unwinding. Keep adapters for exotic calls, host boundaries and functions requiring differing semantics. Numeric entries can use the uniform general body as fallback.
- Add an ordinary `[[Construct]]` entry using the guarded initial shape, a new receiver and the same argument area. Handle return substitution, custom and derived new targets, class restrictions and `super()` with the specified semantics. If `apply` is the expected builtin and its only argument source is a provably unobserved `arguments` view, forward the actual area with its original count. Preserve observable getter order, modified argument aliases, escapes, subclassing and prototype mutations in the fallback. Budget the generic `arguments` materialization speedup separately when this guard cannot be proved.
- **Scope.** `packages/js-engine/src/lowering/index.ts` (`invoke`, `argumentList`, function entry and `new`), `packages/js-runtime/src/objects/functions.ts` (`createNativeSourceFunction`, `sourceFunction`), `objects/call.ts` (`callObject`, `constructObject`), `objects/jobs.ts` (source call state and Script context), `objects/arguments.ts`, `objects/function-intrinsics.ts`, and `packages/ts-native/src/scalar.ts` (entry/call ABI, stack argument area and stack maps).
- **Cost and risk.** High. The same convention must work across AOT and live execution, on arm64 and x86-64, with correct unwinding, rooting, reentry and cross-realm behavior. Preserve legacy caller observation and sloppy mapped arguments, including escaped mappings. Require a traced, ordinary six-argument polymorphic call in tens of retired instructions with zero managed allocations when argument materialization is unobservable. Trace `new`, rest/mapped/spread and the RayTrace forwarding path separately.

## Phase 3 · Primitive operations and lexical representation

- Lower tag tests and primitive equality into predictable inlined operations. Handle object/nullish and numeric comparisons when the tags prove they need no user coercion. Keep inferred values open and honor written contracts. Carry guarded integer or double representations through loops and across calls that preserve the input facts, then widen at explicit boundaries. Resolve global and lexical slots statically where permitted and defer environment construction until capture, eval, suspension or escaping mapped parameters need storage. Reuse the existing native unwinding convention for abrupt values on ordinary paths.
- **Scope.** `packages/js-engine/src/lowering/index.ts` (scope access and arithmetic/equality lowering), `packages/js-runtime/src/objects/equality.ts`, `objects/operators.ts`, `objects/coercion.ts` and `environments/global/scope.ts`, plus `packages/ts-native/src/scalar.ts` for two-word and unboxed value lowering.
- **Cost and risk.** Medium to high. Premature specialization can break negative zero, NaN, BigInt coercion, HTMLDDA equality, prototype and global invalidation, TDZ or closure lifetime. Use the Richards `looselyEqual` sample count and the Navier loop instruction trace as checks on the predicted reductions. Validate direct eval, with, closure capture over suspension, and writes from untyped code to explicitly annotated bindings.

## Phase 4 · Reduce allocation graph size and collection work

- Measure first after the storage and ABI phases. Compact receiver headers, share shape metadata and publish literal and constructor instances in a small nursery fast path using existing managed allocation. Split rarely used exotic state from ordinary receivers. Use frame slots or scalar replacement for provably non-escaping objects, argument views and immutable by-value closure captures. Retain allocation when identity is observable, and account for the remembered writes needed when a value escapes the nursery.
- **Scope.** `packages/js-runtime/src/objects/operations.ts` (`allocateObject`), `objects/functions.ts` (closure construction), lowered object and closure allocation in `packages/js-engine/src/lowering/index.ts` and `packages/ts-native/src/scalar.ts`, plus `packages/native-runtime/src/generational.ts` and tracing/stack-map machinery.
- **Cost and risk.** Medium for compact allocation using the existing collector and high for general escape analysis. Rooting, weak references, finalization and prototype or contract transitions constrain elimination. Measure managed allocations and bytes per constructor, remembered edges, nursery survival and main-thread vs worker collection. Use a moving-GC test with a live promoted value and an escape that materializes before a user-observable operation.

## Phase 5 · Optimize generated guest code with the new representations

The potential speedup here is less directly measurable at the current head. Prototype this phase after the object and call representations stabilize. After re-profiling, make the AOT compiler combine guarded receiver facts, exact constructor shapes and closure targets across functions. Inline small methods with an explicit code-size budget, keep primitive values in registers across the resulting graph, and remove redundant projection, bounds and shape checks only when invalidation or slow-path transfer remains correct. Profile-guided clones are a follow-up for genuinely hot polymorphic sites. Validate the generic entry on guard misses so unprofiled programs retain predictable cost. Inspect the generated code of `lin_solve`, `schedule`, `Plan.execute` and the RayTrace intersection routines. A 25–50% reduction of the currently attributed generated-JS samples would model baseline time savings of 9–19% for Richards, 5–11% for DeltaBlue, 13–26% for NavierStokes and 3–5% for RayTrace. Treat that as a sensitivity check. The Richards trace now identifies some generated work specifically in guarded property reads, call setup and tagged comparisons. Re-profile those functions after the earlier phases before assigning more of the residual to inlining.

This phase belongs in `packages/js-engine/src/lowering` and the analysis and native value lowering in `packages/ts-native/src`. Its cost is high and its risks are code size, compile time, preserving side-effect order and keeping every guarded fallback equivalent. Compare whole-program or profile-selected variants against the same unmodified fixtures and retest frozen self-build stages at each accepted boundary.

## Evidence required at each phase

Use the existing locked, paired protocol on all four Octane programs, the eight original call/loop kernels and the fifteen generality kernels. Report instructions and allocation counts separately from timings and capture the guard-hit and miss paths at representative sites. Re-profile before expanding the change if the expected dominant work remains. Require frozen self-build output equivalence, stage 2 and 3 agreement, no wall-time or RSS regression, native Test262 selections at their exact denominators, and zero changes to the ledger's 200 outcomes. Keep native path tests for receiver and prototype mutation, getter and proxy fallbacks, cross-realm entry, mapped arguments, GC across unwinding and every abrupt boundary changed by the phase.
