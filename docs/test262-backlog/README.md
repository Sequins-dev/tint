# Test262 implementation backlog

Planning index for the active goal: **over 90% native passes on the complete pinned
Test262 suite** (revision `91c70759363c46557b694792bf34a2551a7af5ba`, 103,264
variants). The whole-suite native pass rate is **unmeasured**. This backlog ranks
the broad gaps that block that goal. It does not report coverage. Current status
lives in the [coverage dashboard](../test262.md), the
[group inventory](../test262-inventory.md) and its
[v67 snapshot](../results/test262-native-group-inventory-v67.json).

Captured on 2026-11-04 from source, saved reports and pinned-suite metadata. It
contains planning facts, not run evidence. The v9 full survey
(`docs/results/test262-full-suite-native-v9.jsonl`) was still running. Its
newline-complete prefix had **~600 observations**, all from `annexB/built-ins/*`,
`annexB/language/comments` and part of `annexB/language/eval-code`. That prefix is
too small to rank language or built-in gaps. All 102 eval-code observations in it
are `unsupported`, which matches RT-EVAL below. **This is a partial, unpublished
journal prefix, not a pass rate.**

## How to read this table

- **Status**: `missing` means no implementation exists in source. `partial` means
  an implementation exists and a measured selection still has non-passes.
  `unmeasured` means no current complete native selection exists, so the size of
  the gap is unknown. `stale` means the only reports predate later fixes
  (for example, the 2026-10-31 language selections) and need a rerun before their
  ratios describe current code.
- **Variants** are pinned-suite variants in the directly owned directories, and
  sometimes file counts for cross-cutting uses. These are populations, not
  expected gains. Overlapping rows must not be added together.
- **Readiness**: `plan ready` means a focused plan exists here. `needs plan` means
  the next step is a fresh planning task. `blocked` means the gap waits on another
  row. `wait v9` means the v9 survey should finish before planning, because the
  failure clusters are unknown.
- Priority uses population, independence and effort. It is a recommendation, not
  a commitment.

## Uncertainty

- The ratio of passes to failures inside LANG-CORE, LANG-OTHER, BI-CORE and
  TEMPORAL-CORE is unknown. Do not prioritize inside those rows until the v9
  survey finishes. Then use a complete-family extraction from that single journal
  (`tools/test262-native-extract.ts`), not cross-snapshot sums.
- Cross-cutting counts such as "files calling `eval(`" come from a text scan of
  test bodies with frontmatter removed. They overcount literal mentions and
  undercount indirect uses. Treat them as order-of-magnitude dependency signals.
- "No source match" means no installer or identifier was found under
  `packages/*/src` on 2026-11-04. It does not account for the parent's
  uncommitted WIP outside INTL-RTF.
